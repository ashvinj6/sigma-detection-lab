# Sigma Detection Lab

Sigma detection rules for Windows attack techniques, mapped to MITRE ATT&CK
and tested against logs exported from my own lab. Clone it, run one command,
and you can see which attacks each rule catches and what normal activity it
flags by mistake.

## Why I built this

> Draft, to be rewritten in my own words in Phase 4.

I wanted to learn detection engineering the way it is actually done:
write a rule, run the real attack, look at what the logs show, and find
out where the rule breaks. Each technique gets a write-up in `docs/`
covering what the rule looks for, how I tuned it, and how an attacker could
get past it.

## Try it

Needs Python 3.11 or newer.

```
git clone https://github.com/ashvinj6/sigma-detection-lab.git
cd sigma-detection-lab
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest
```

`pytest` replays every fixture against its rule, validates every rule with
pySigma, and checks the repo's own rules (synthetic data is labeled, every
rule has fixtures and a write-up with known blind spots).

## How it works

Each Sigma rule is converted to SQL with pySigma's SQLite backend, after the
Sysmon and Windows pipelines add the `Channel` and `EventID` conditions a
SIEM would. Fixture events are loaded into an in-memory SQLite table and the
query runs against them. An attack run counts as detected if any of its
events match. A benign event that matches is a false positive. Details are in
[CLAUDE.md](CLAUDE.md) and [fixtures/README.md](fixtures/README.md).

## Layout

| Path | What is there |
|---|---|
| `rules/` | one Sigma rule per technique |
| `fixtures/attack/`, `fixtures/benign/` | real exported events from the lab |
| `fixtures/synthetic/` | placeholder events, never counted |
| `tests/` | replay harness and tests |
| `tools/` | `evtx_to_fixture.py`, `generate_readme.py` |
| `docs/` | one write-up per rule, and [LAB_SETUP.md](docs/LAB_SETUP.md) |

## Safety

No malware, exploit code, or attack tools are in this repo. Attacks are
run in an isolated VM using [Atomic Red Team](https://github.com/redcanaryco/atomic-red-team)
tests, referenced by GUID in each fixture's metadata.
